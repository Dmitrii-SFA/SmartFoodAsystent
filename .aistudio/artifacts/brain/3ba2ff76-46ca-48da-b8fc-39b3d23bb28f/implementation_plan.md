# Подключение базы ключей USERS_KV (Cloudflare KV)

Настройка прямой привязки хранилища `USERS_KV` (`f88a2d8d574b41f59e6db567479fb7db`) к облачному воркеру и поддержка любого формата значений при ручном добавлении ключей в панели Cloudflare.

## User Review & Critical Decisions

> [!IMPORTANT]
> Параметры хранения и проверки ключей согласованы на основе ваших ответов и скриншота из панели Cloudflare:

- **Подтверждённое решение 1 (Структура хранения в `USERS_KV`)**: Каждый ключ доступа хранится как отдельная запись (Key) в пространстве имён `USERS_KV` с Namespace ID `f88a2d8d574b41f59e6db567479fb7db`.
- **Подтверждённое решение 2 (Универсальный формат Value)**: При добавлении нового ключа вручную в Cloudflare KV его значением (Value) может быть как JSON (`{"remaining": 500, "devices": []}`), так и просто число (например, `500`) или любой текст/метка (например, `active`). При первой активации приложение автоматически инициализирует для такого ключа баланс (500 запросов либо указанное число) и список привязанных устройств.

## 1. Overview & Core Concept

- **Что делает изменение**:
  1. Прописывает жёсткую привязку пространства имён `USERS_KV` с ID `f88a2d8d574b41f59e6db567479fb7db` в конфигурации деплоя Cloudflare, чтобы при любых обновлениях привязка к базе ключей сохранялась автоматически.
  2. Обновляет логику чтения записей из `USERS_KV` так, чтобы ключи, созданные вручную в панели Cloudflare с простым числом или текстом в поле Value, сразу распознавались как действительные и автоматически преобразовывались в рабочую структуру учёта лимитов и устройств.
- **Ключевая ценность**: Вы можете добавлять новые ключи прямо через веб-интерфейс Cloudflare в `USERS_KV` в один клик (указав в качестве значения `500`, любой комментарий или JSON), и они мгновенно начнут работать у пользователей.

## 2. User Experience & Visual Design

- **Путь пользователя и администратора**:
  1. Вы открываете `USERS_KV` в панели Cloudflare и добавляете запись: в поле **Key** вводите сам ключ доступа, а в поле **Value** — `500` (или любой текст/JSON).
  2. Пользователь вводит этот ключ в окне «Ключ доступа» в приложении и нажимает «Активировать».
  3. Сервер находит запись в `USERS_KV`, привязывает текущее устройство (до 2 устройств на ключ), сохраняет актуальный остаток запросов в `USERS_KV` и отображает статус активации и баланс в интерфейсе.
- **Защита от автозаглавных букв на телефонах**: Если при вводе с телефона первая буква ключа изменила регистр, сервер сначала ищет точное совпадение, а затем проверяет варианты в верхнем и нижнем регистре, чтобы избежать ложной ошибки «Неверный ключ доступа».

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Автоматическая нормализация значения ключа в `USERS_KV`**
  - *Выбранный подход*: Если значение ключа в `USERS_KV` не является JSON-объектом (например, записано число `500` или строка `"активен"`), парсер не отклоняет ключ, а создаёт валидный профиль ключа (`remaining: <число или 500>`, `devices: []`) и при активации записывает его обратно в `USERS_KV` в формате JSON.
  - *Почему*: Раньше парсер требовал строго JSON-объект и возвращал ошибку «Неверный ключ доступа» для любых ключей, созданных вручную с числовым или текстовым значением.
- **Решение 2: Фиксация Namespace ID в конфигурации воркера**
  - *Выбранный подход*: Добавление привязки `USERS_KV` с ID `f88a2d8d574b41f59e6db567479fb7db` непосредственно в конфигурацию деплоя Cloudflare.
  - *Почему*: Гарантирует, что воркер всегда подключён именно к вашему списку `USERS_KV` со скриншота.

## 4. Technical Architecture & Data Strategy *(Technical Reference)*

```
┌────────────────────────────────────────────────────────────────────┐
│                   Окно «Ключ доступа» (Клиент)                     │
│        Ввод ключа активации + передача заголовка x-device-id       │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │ POST /api (action: "verify_key")
                                  ▼
┌────────────────────────────────────────────────────────────────────┐
│              Cloudflare Worker / Pages API + Dev Proxy             │
│  1. Проверка MASTER_KEY (безлимитный доступ владельца)             │
│  2. Поиск ключа в USERS_KV (ID: f88a2d8d574b41f59e6db567479fb7db)  │
│     • Точное совпадение Key (с поддержкой регистронезависимого     │
│       поиска при вводе с мобильной клавиатуры)                     │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │
                                  ▼
┌────────────────────────────────────────────────────────────────────┐
│            Универсальный парсер записи из USERS_KV                 │
│  • JSON {"remaining": N, "devices": [...]} ──► использует как есть │
│  • Число (например, "500" или "300")       ──► remaining = N       │
│  • Любой текст / метка                     ──► remaining = 500     │
│  ► Привязка устройства (макс. 2) и сохранение JSON в USERS_KV      │
└────────────────────────────────────────────────────────────────────┘
```

- **Структура данных в `USERS_KV`**:
  - **Key**: строка ключа доступа (например, `SMART-2026-XXXX`).
  - **Value (на входе при создании вручную)**: число (`500`), произвольная строка (`active`) или JSON (`{"remaining":500,"devices":[]}`).
  - **Value (после активации и при работе)**: `{"remaining": 499, "devices": ["dev_abc123"]}`.
