# Исправление ошибки 405 Method Not Allowed в Cloudflare и переход на Gemini 3.5 Flash-Lite

Устранение ошибки `405 Method Not Allowed` при отправке фотографий и JSON-запросов на `api.smartfoodasystent.workers.dev` путём добавления серверного обработчика Cloudflare Worker (`worker.js`) и конфигурации `wrangler.toml` с приоритетом воркера над статическими файлами, а также переключение ИИ-модели на **Gemini 3.5 Flash-Lite** с автоматическим резервным переключением (fallback) на стороне воркера.

## User Review & Critical Decisions

> [!IMPORTANT]
> Ниже зафиксированы подтверждённые вами архитектурные решения перед внесением изменений в код проекта.

- **Конфигурация Cloudflare в репозитории**: В корень проекта добавляются готовые файлы `worker.js` и `wrangler.toml` с параметром `run_worker_first = true`, чтобы Cloudflare направлял все `POST` и `OPTIONS` запросы в серверный обработчик воркера, а не в статический сервер (который блокирует `POST` кодом `405`).
- **Модель Gemini 3.5 Flash-Lite с фоллбэком**: Клиент передаёт идентификатор `gemini-3.5-flash-lite`, а воркер при обращении к Google Gemini API использует цепочку автоматического резервирования (`gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` → `gemini-2.5-flash-lite` → `gemini-flash-latest`), если конкретный алиас модели недоступен в регионе или API-версии.

---

## 1. Overview & Core Concept

- **Что делает изменение**: Превращает деплой в Cloudflare из чисто статического хостинга в полноценный гибридный сервис (Worker API + статика), способный принимать `POST`-запросы с изображениями этикеток, тарелок, рецептами и сообщениями чата.
- **Ключевая ценность**: Камера и ИИ-функции приложения работают без ошибки `405 Method Not Allowed` как при обращении к выделенному домену `https://api.smartfoodasystent.workers.dev`, так и при запуске на одном домене со статикой, а секретный ключ `GEMINI_API_KEY` остаётся защищённым внутри окружения Cloudflare.

---

## 2. User Experience & Visual Design

- **Прозрачная работа камеры и ИИ**: При съёмке этикетки продукта, блюда на тарелке или генерации рецепта приложение отправляет `POST`-запрос и получает распознанные нутриенты без сбоев `405` или ошибок CORS.
- **Отображение модели в интерфейсе**: В заголовке и приветствии ИИ-ассистента отображается актуальная версия **Gemini 3.5 Flash-Lite** (`gemini-3.5-flash-lite`).
- **Обработка ошибок и квот**: Сохраняется существующая логика суточных лимитов (20 запросов в сутки без ключа, 100 запросов в сутки с ключом доступа, интервал 10 секунд) и окно «Полный доступ на 1 год».

---

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Приоритет воркера над статикой (`run_worker_first = true`)**
  - *Выбранный подход*: В `wrangler.toml` указывается точка входа `main = "worker.js"` и настройка `[assets]` с `run_worker_first = true`. Воркер перехватывает все `OPTIONS` и `POST` запросы, а `GET`-запросы к фронтенду передаёт в `env.ASSETS.fetch(request)`.
  - *Почему*: По умолчанию Cloudflare Workers Static Assets обслуживает статику до запуска воркера и мгновенно возвращает `405 Method Not Allowed` на любой `POST`-запрос.
- **Решение 2: Цепочка фоллбэка для модели `gemini-3.5-flash-lite`**
  - *Выбранный подход*: Клиент запрашивает `model: "gemini-3.5-flash-lite"`. Воркер пытается вызвать указанную модель в Google Gemini REST API (`v1beta`), а при ответе `404 Not Found` от Google автоматически повторяет запрос через актуальный лёгкий Flash-Lite идентификатор (`gemini-3.1-flash-lite` / `gemini-2.5-flash-lite`).
  - *Почему*: Гарантирует бесперебойную работу распознавания фото и генерации рецептов независимо от того, какое точное имя алиаса активировано в аккаунте Google AI Studio.

## 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Клиент (React PWA / Камера / Чат)                    │
│  POST https://api.smartfoodasystent.workers.dev                         │
│  Headers: { "Content-Type": "application/json", "x-access-token": ... } │
│  Body: { model: "gemini-3.5-flash-lite", contents: [...], ... }         │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│             Cloudflare Worker (worker.js + wrangler.toml)               │
│  1. OPTIONS -> 204 No Content + CORS заголовки                          │
│  2. POST    -> Чтение JSON + проверка env.GEMINI_API_KEY                │
│  3. GET     -> Раздача статики через env.ASSETS (или JSON статус API)   │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                     Google Gemini API (v1beta REST)                     │
│  Попытка 1: models/gemini-3.5-flash-lite:generateContent                │
│  Фоллбэк (при 404): gemini-3.1-flash-lite -> gemini-2.5-flash-lite      │
└─────────────────────────────────────────────────────────────────────────┘
```

- **Маршрутизация запросов в `worker.js`**:
  - Поддержка `OPTIONS` для прохождения браузерного CORS preflight при кросс-доменных запросах на `api.smartfoodasystent.workers.dev`.
  - Поддержка `POST` на любом пути (`/`, `/api/*`), чтение `contents`, `generationConfig` и `systemInstruction`, проксирование в Gemini API с секретом `env.GEMINI_API_KEY` и возврат JSON-ответа клиенту.
- **Обновление клиентского слоя**:
  - В запросах к воркеру передаётся `model: "gemini-3.5-flash-lite"`.
  - Во всех текстовых подписях ИИ-чата и конфигурации по умолчанию указывается `Gemini 3.5 Flash-Lite` (`gemini-3.5-flash-lite`).
