# Устранение ошибки 405 (Method Not Allowed) на Cloudflare

Этот план устраняет причину ошибки `405 Method Not Allowed` при отправке `POST`-запросов к ИИ после развёртывания приложения на Cloudflare (как в режиме **Cloudflare Workers со статическими ассетами**, так и в режиме **Cloudflare Pages**).

## Согласованные решения

> [!IMPORTANT]
> Причина ошибки `405 Method Not Allowed`: по умолчанию слой раздачи статики Cloudflare (`ASSETS` / `./dist`) перехватывает входящие запросы **до** запуска серверного скрипта воркера. Так как сервер статики принимает только `GET` и `HEAD`, любой `POST`-запрос к `/api` отклоняется кодом `405`, не доходя до кода воркера.

- **Универсальная поддержка Cloudflare Workers и Cloudflare Pages**: конфигурация настраивается так, чтобы серверный обработчик гарантированно перехватывал `POST` и `OPTIONS` запросы раньше статики при любом способе деплоя в панели Cloudflare.
- **Умная маршрутизация запросов с фоллбэком**: клиент отправляет запросы на `/api` текущего домена, а при необходимости (например, если фронтенд открыт на отдельном домене или превью-ссылке) автоматически повторяет запрос на `https://api.smartfoodasystent.workers.dev/api`.

---

## 1. Обзор и суть решения

- **Что делает изменение**: гарантирует, что все `POST` и `OPTIONS` запросы к `/api` обрабатываются серверным кодом Cloudflare Worker с ключом `env.GEMINI_API_KEY`, а обычные `GET`-запросы к интерфейсу приложения отдают статические файлы из `./dist`.
- **Для кого**: для всех пользователей приложения на смартфонах и компьютерах, использующих ИИ-оценку продуктов, распознавание этикеток/блюд по фото, генерацию рецептов и ИИ-чат.
- **Ключевая ценность**: полное устранение ошибки `405 Method Not Allowed` независимо от того, развёрнут ли проект через Cloudflare Workers (`wrangler`) или через Cloudflare Pages (Git-интеграция).

---

## 2. Пользовательский опыт и поведение при запросах

- **Прозрачная отправка ИИ-запросов**: при нажатии кнопок «ИИ по названию», «Фото этикетки», «Фото блюда», «Сгенерировать рецепт» или отправке сообщения в чат запрос мгновенно проходит через серверный прокси без ошибок `405` и без проблем с CORS.
- **Понятная диагностика**: если в настройках Cloudflare ещё не задан секрет `GEMINI_API_KEY`, интерфейс покажет понятное сообщение от сервера вместо пустой ошибки сети.

---

## 3. Ключевые архитектурные решения

1. **Приоритет воркера над статикой (`run_worker_first: true`)**:
   - *Выбранный подход*: добавление `"run_worker_first": true` в блок `assets` конфигурации Wrangler.
   - *Почему*: без этого флага Cloudflare проверяет наличие маршрута в статических файлах и сразу возвращает `405 Method Not Allowed` на любой `POST`-запрос, даже не вызывая `worker.js`.
2. **Совместимость с Cloudflare Pages (`_worker.js` и Pages Functions)**:
   - *Выбранный подход*: автоматическое включение серверного обработчика в сборку `./dist` (через `_worker.js` и `.assetsignore`), а также поддержка маршрута Pages Functions.
   - *Почему*: если проект подключён через Git как Cloudflare Pages, платформа ищет обработчик внутри папки сборки `./dist` или `functions/`. Наличие обоих механизмов исключает ошибку `405` при любом типе деплоя.
3. **Двухступенчатая отправка с клиента (Относительный `/api` -> Полный URL воркера)**:
   - *Выбранный подход*: клиент сначала обращается к `/api` на текущем домене (что исключает CORS-блокировки, когда сайт и воркер работают на одном домене), а при коде `404`/`405` или сетевой ошибке автоматически выполняет фоллбэк на `https://api.smartfoodasystent.workers.dev/api`.
   - *Почему*: приложение работает без сбоев как на основном домене Cloudflare, так и на внешних превью-доменах и в локальной среде разработки.

---

## 4. Техническая архитектура и поток данных

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     Клиентское приложение (React PWA)                    │
│  (Оценка продукта / Сканирование фото / Генерация рецепта / ИИ-чат)     │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │
         1. POST /api (текущий домен)│  2. Фоллбэк при 404/405 или другом домене:
            + заголовок              │     POST https://api.smartfoodasystent.workers.dev/api
            x-access-token           ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                Серверный слой Cloudflare (Workers & Pages)               │
│  • wrangler.json: assets.run_worker_first = true                         │
│  • Перехват всех OPTIONS (204 CORS) и POST (/api) до проверки статики    │
├────────────────────────────────────┬─────────────────────────────────────┤
│ POST / OPTIONS запросы             │ GET запросы (HTML, JS, CSS, иконки) │
▼                                    ▼                                     │
┌──────────────────────────────────┐ ┌─────────────────────────────────────┐
│ Прокси к Google Gemini REST API  │ │ Раздача статики (env.ASSETS.fetch)  │
│ • Чтение env.GEMINI_API_KEY      │ │ • Отдача файлов из ./dist           │
│ • Передача contents и            │ │ • SPA-фоллбэк на index.html         │
│   generationConfig               │ └─────────────────────────────────────┘
└──────────────────────────────────┘
```

### Обработка состояний и запросов
- **Заголовки и CORS**: серверный обработчик отвечает на `OPTIONS`-запросы статусом `204` с разрешающими заголовками `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: POST, GET, OPTIONS` и `Access-Control-Allow-Headers: Content-Type, x-access-token`.
- **Передача параметров генерации**: помимо `contents`, прокси передаёт `generationConfig` (включая `responseMimeType: "application/json"`), чтобы Gemini всегда возвращал строго валидный JSON для карточек продуктов и рецептов.
- **Локальная среда разработки**: локальный сервер разработки также поддерживает маршрут `POST /api` в том же формате, чтобы проверка в превью работала идентично продакшену на Cloudflare.
